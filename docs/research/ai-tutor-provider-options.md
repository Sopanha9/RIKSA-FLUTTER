# AI tutor provider options

Current as of 2026-08-27. This is a competition-oriented decision note, not a long-term procurement review.

- **Recommendation: keep OpenRouter for the competition, but put it behind the app's backend and pin a primary model plus one fallback.** Its unified OpenAI-compatible endpoint minimizes integration work, while provider routing and model fallbacks can recover from rate limits, outages, and some moderation failures. That gives Riksa a quick path to model comparison without rewriting the app. Do not expose a shared API key in the Flutter binary. [OpenRouter quickstart](https://openrouter.ai/docs/quickstart), [provider routing](https://openrouter.ai/docs/guides/routing/provider-selection), [model fallbacks](https://openrouter.ai/docs/guides/routing/model-fallbacks)

- **Do not build the demo around OpenRouter's free models.** The free plan is limited to 50 requests/day, and OpenRouter says free models are generally unsuitable for production. Pay-as-you-go passes through model token prices but currently adds a 5.5% credit-purchase fee; the trade is convenience, consolidated billing, and access to 400+ models/70+ providers. Use a cheap paid model for normal tutoring and a stronger fallback only for difficult questions. [OpenRouter pricing](https://openrouter.ai/pricing), [OpenRouter FAQ](https://openrouter.ai/docs/faq)

- **OpenRouter reduces model lock-in, but adds gateway and policy complexity.** It supports streaming, image inputs, and schema-constrained structured output on compatible models. However, capabilities and data handling vary by the selected downstream model/provider, so set `require_parameters: true` for schemas and explicitly enforce `data_collection: "deny"` or `zdr: true` instead of relying on defaults. OpenRouter says prompt/response retention by OpenRouter is opt-in, while request metadata is retained; downstream provider policies still apply. [structured outputs](https://openrouter.ai/docs/guides/features/structured-outputs), [image inputs](https://openrouter.ai/docs/guides/overview/multimodal/image-understanding), [data collection](https://openrouter.ai/docs/guides/privacy/data-collection), [zero data retention](https://openrouter.ai/docs/guides/features/zdr)

- **Best single-vendor alternative for this Flutter app: Gemini through Firebase AI Logic.** Google provides a Flutter/Dart SDK that can call Gemini directly through a Firebase proxy, keeps Gemini authorization off the device, and integrates App Check. It supports streamed text, multimodal files, structured JSON, chat, image generation/editing, tools, and bidirectional audio through the Live API. The Gemini Developer API has a free tier; on the paid tier Google says prompts/responses are not used to improve its products. This is the fastest route if a live voice tutor or “photograph a problem and discuss it” is the centerpiece. [Firebase AI Logic Flutter setup](https://firebase.google.com/docs/ai-logic/get-started?platform=flutter), [Firebase AI Logic overview](https://firebase.google.com/docs/ai-logic), [Gemini pricing](https://ai.google.dev/gemini-api/docs/pricing), [Gemini zero-data-retention guidance](https://ai.google.dev/gemini-api/docs/zdr)

- **OpenAI direct is polished but less compelling for a short competition build unless one of its native tools is essential.** The Responses API offers streaming, image/file/audio inputs, function calling, and strict JSON-schema outputs; current small models are inexpensive but API free access is model-dependent and some models list no free tier. OpenAI says API data is not used for training by default, while default abuse-monitoring logs may retain customer content for up to 30 days; approved organizations can request stricter controls. Direct integration improves feature consistency and removes the extra gateway, but increases vendor lock-in. [GPT-5 model capabilities and pricing](https://developers.openai.com/api/docs/models/gpt-5), [Responses API and structured outputs](https://platform.openai.com/docs/api-reference/responses), [API data controls](https://platform.openai.com/docs/models/default-usage-policies-by-endpoint)

- **Anthropic direct is a quality-focused option, not the best cost/setup differentiator here.** Claude's API supports text/image messages, streaming, tool use, and structured outputs. Anthropic's published pricing positions Haiku as the lower-cost tier and Sonnet/Opus above it; new users may receive only a small amount of test credit. Anthropic says API inputs/outputs are normally deleted within 30 days, subject to stated exceptions or a separate zero-retention agreement. Direct Claude makes sense only if tutor evaluations show a material teaching-quality win. [Claude platform feature overview](https://platform.claude.com/docs/en/home), [Claude pricing](https://docs.anthropic.com/en/docs/about-claude/pricing), [Anthropic retention](https://privacy.claude.com/en/articles/7996866-how-long-do-you-store-my-organization-s-data)

- **On-device AI is a memorable bonus, not the primary tutor.** Android ML Kit GenAI runs Gemini Nano locally, streams responses, works offline, and has no per-call server cost, but device support is limited and model behavior varies by device/version. Apple's Foundation Models framework similarly supports local generation, structured output, and tools only on Apple-Intelligence-capable devices and is exposed through native Swift rather than a first-party Flutter API. Use on-device inference for a small offline feature—lesson recap, reflection prompts, or draft hints—with the cloud tutor as fallback. [ML Kit GenAI overview](https://developers.google.com/ml-kit/genai), [Apple Foundation Models](https://developer.apple.com/documentation/FoundationModels/), [Apple availability guidance](https://developer.apple.com/documentation/FoundationModels/generating-content-and-performing-tasks-with-foundation-models)

The provider itself will not make the entry stand out. The strongest demo is a **Khmer/English Socratic tutor grounded in the visible lesson**, showing which lesson context it used, accepting a photo or voice question, returning one hint at a time, and writing a short reflection to the learner's journal. OpenRouter is a good launch layer for that; Firebase AI Logic is the better swap only if native real-time voice and the fastest secure client-side Flutter integration are central to the judging demo.
